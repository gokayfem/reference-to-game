# Scope and honest limits

Input-agnostic means the workflow can start from different kinds and combinations of evidence, without requiring one provider, genre, fixed grid, number of shots or art style. It does not mean every file format is decoded automatically, every brief is sufficient to infer hidden mechanics, or every outcome will match the reference perfectly.

The CLI natively inventories common media/document/model formats, hashes files and records HTTP(S) links. It inspects Pillow-readable images, text previews and ffmpeg-readable audio/video. Models, PDFs, unusual codecs and inaccessible links require an appropriate external viewer or connector. Audio-led and text-only tasks need authored visual direction; this must be disclosed.

The default implementation profile is browser-based Three.js, with engine-neutral contracts and optional runtime helpers. Other engines can follow the workflow, but this release does not contain Unity/Godot/Unreal project generators or verified engine adapters.

fal is optional and requires authorization, configured credentials, current schema/pricing review and a budget. The adapter has been tested offline with fake transports. No paid inference is needed for toolkit tests. It does not select models or manufacture price guarantees.

The example games are real playable implementations. Their original project reports provide playthrough/performance evidence with device-specific limitations. This repository's validation records distinguish newly rerun tests/builds from those historical reports. There is no claim that four attractive examples prove the packaged skill works on every input or improves any agent by a measured percentage.
